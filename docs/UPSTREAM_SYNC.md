## 本轮检查发现并修复的问题

- WebDAV 写后读回失败曾报告成功；现在未完成验证就报失败。
- HTTP 412 后曾取消条件再写一次，可能覆盖并发更新；现在相同内容只视为幂等成功，不再重复 PUT。
- 自动同步只监听歌单条数，遗漏改名、加歌和排序；失败还会确认同步进度。现在监听内容，失败重试，同步中新增编辑保留待同步状态。
- GitHub 分支读失败曾被当成空仓库；现在停止同步，并按不可变 commit 读取数据。
- 歌词来源切换后，旧请求可能回填缓存/覆盖新歌词；现在按请求代次隔离并传播取消。
- 队列清空/准备期间暂停未完整取消播放加载；切歌时收听时间可能记到下一首；重复歌曲排序会定位到错误条目。增加会话检查并修复持久化。
- 取消后立即重试可能让旧下载恢复发布；下载文件名相同可能覆盖不同平台歌曲；并发下载记录落盘可能倒退。采用独立尝试身份、独立临时文件、文件名身份摘要及串行持久化。
- 网络响应与图片原先在完全读入后才检查大小；改为限额流式读取（含 gzip 解压），跨域重定向剥离凭据，拒绝跨域写入和 HTTPS 降级。
- 设置后台写盘与退出 flush 可能顺序倒退；写盘与快照现在共用锁。
- 实机短窗口中播放按钮被挤扁、队列等次级操作被裁切；改为播放控制区可滚动，横屏歌词区仍独立保持可见。
- 原 CI 文件在 `ci/`，GitHub 不会自动执行；已迁入 `.github/workflows/`，加入离线回归测试与报告上传。

## 必须保留的限制

1. **新版归档同步协议 3/4 未移植。** 原版当前使用 `neriplayer-sync-v3.manifest` 和分片归档。
   发现该文件、协议检测失败或备份版本未知时，本客户端拒绝按旧格式同步；不会删除、降级或覆盖归档。
   旧 JSON / ZSTD-Protobuf / GZIP-Protobuf / Base64-GZIP 通道继续兼容。需要与最新版 Android 同步时，不应把本版本视为已经兼容；也不要通过删除 manifest 强行同步。
2. 未新增 Navidrome / OpenSubsonic（上游仍标记预览）、YouTube Music、一起听、自研 DSP / AutoEQ、USB 独占或全量英文界面。
   这些是独立的大型功能，不应通过复制 Android 源文件或合并仓库历史来伪装实现。
3. Android 小组件、前台服务、Root / Shizuku、ColorOS 锁屏、预测返回和 GNOME 托盘修复不适用于 Windows。
4. 离线回归测试不等于平台接口承诺。实际登录、CC 轨道可用性、会员内容、SMTC/媒体键、真实账号跨设备同步及安装升级仍需真实环境验收。
